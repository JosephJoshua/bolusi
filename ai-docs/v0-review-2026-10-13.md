## Confirmed findings

### 1. HIGH — cross-store PIN reset authorization bypass

An isolated PostgreSQL 16 endpoint probe used one tenant with two stores. The actor was store-A-only, held `store_owner`, and used a store-A device. The target belonged only to store B. Posting a valid newer target verifier returned HTTP `200`, `{ "applied": true }`, and wrote the target verifier (`ENDPOINT_PROBE_EXIT=0`).

`apps/server/src/routes/users.ts:381` checks the actor's permission in the acting device's store but does not verify that the target's store memberships are within the actor's granted stores before the write at line 417. This contradicts `ai-docs/02-permissions.md:151` rule 3. Two independent reviewers reproduced the issue; one used a real PostgreSQL endpoint fixture.

Filed as `ai-docs/tasks/213-pin-verifier-cross-store-reset.md`. This is the primary v0 blocker.

### 2. HIGH — nightly chaos coverage is not completing

The five latest inspected `chaos-nightly` jobs from October 8–12, 2026 were cancelled. The October 12 run started at `2026-10-12T09:37:15Z` and ended at `15:37:48Z`, exhausting the workflow's 360-minute timeout. CHAOS-02 schedules 100 full-volume seeds without a corresponding runtime budget. A timed-out run cannot certify the declared scenario coverage, and previously logged CHAOS-03 failures require separate triage.

Filed as `ai-docs/tasks/214-nightly-chaos-runtime-budget.md`.

### 3. MEDIUM — nightly reproduction guard fails at nightly scale

The focused test under `CHAOS_SCALE=4` fails because `packages/harness/scenarios/reproducibility.test.ts:84` expects a scale-1 command while the reporter correctly emits scale 4. This is an independent red in the nightly environment and can obscure actual scenario results.

Filed as `ai-docs/tasks/215-nightly-reproduction-meta-test-scale.md`.

### 4. MEDIUM, conditional — projection rebuild can double-apply interleaved pulled operations

Two independent reviewers reproduced a paused rebuild followed by an out-of-order pull and resume using an isolated SQLite notes applier. The observed projection had `edit_count=4` where the canonical fold gives `2`. The rebuild cursor and the pull/refold path are not coordinated.

No production caller of `rebuild` was found in this review, so this is a confirmed core API/harness defect, not evidence of current live user data corruption. Filed as `ai-docs/tasks/216-rebuild-interleaved-pull-double-applies.md`.

### 5. MEDIUM, conditional — version-gated rebuild skips an incomplete same-version rebuild

After an interrupted rebuild leaves a durable in-progress cursor while the module version remains unchanged, a fresh engine's `rebuildIfVersionChanged` returns `{ rebuilt: false }` without inspecting that cursor. An explicit rebuild resumes correctly. No production caller of the version-gated method was found.

Filed as `ai-docs/tasks/217-rebuild-same-version-incomplete-cursor.md`.

### 6. MEDIUM — local secrets scan fails on generated artifacts

The working-tree scan reports three redacted `generic-api-key` matches in ignored Android release bundles and sourcemaps under `.claude/worktrees/.../android/app/build/`. The full Git history scan is clean. This does not yet prove the values are secrets or false positives; they must be classified privately before changing scanner scope.

Filed as `ai-docs/tasks/218-local-secrets-scan-generated-artifacts.md`.
